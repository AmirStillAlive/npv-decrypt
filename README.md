# NPV Decrypt — دیکریپت کانفیگ‌های NPV Tunnel

باز کردن فایل‌های کانفیگ `.npvt` که اپ **NPV Tunnel / NapsternetV** تولید می‌کند — هم به‌صورت ابزار خط فرمان پایتون، هم به‌صورت یک صفحهٔ وب که **کاملاً داخل مرورگر** کار می‌کند و فایل را به هیچ سروری نمی‌فرستد.

**وب‌اپ آنلاین:** https://amirstillalive.github.io/npv-decrypt/

---

## چرا؟

کانفیگ‌های توزیع‌شده در کانال‌های تلگرامی با پسوند `.npvt` «رمزنگاری» شده‌اند. این رمز در عمل چیزی برای محافظت نیست: کلید اصلی هرگز در برنامه نیست و به‌جای آن یک **AES-128-CTR با کلید white-box** پیاده شده — یعنی جدول‌های رمز در خود اپ جاسازی شده‌اند. همان جدول‌ها عمومی‌اند، پس رمزگشایی بدون هیچ کلید مخفی ممکن است.

این مخزن همان رمزگشایی را پیاده‌سازی می‌کند تا ببینید دقیقاً چه چیزی دارید استفاده می‌کنید: سرور کیست، ترافیک از کجا رد می‌شود و چه تنظیماتی داخل کانفیگ است.

---

## استفاده · نسخهٔ خط فرمان (پایتون)

```bash
python decrypt_npvt.py <پوشه یا فایل ورودی> [پوشه خروجی]
```

بدون وابستگی خارجی (فقط کتابخانهٔ استاندارد). جدول‌ها در `npv_tables.json` کنار همان اسکریپت است. خروجی هر فایل، یک `.txt` با JSON خوانا است.

```bash
python verify.py <پوشه حاوی .npvt>    # هش SHA-256 خروجی هر فایل را چاپ می‌کند
```

## استفاده · وب‌اپ (GitHub Pages)

در `web/` یک اپ React + Tailwind v4 است که خروجی build آن در `docs/` می‌نشیند و GitHub Pages از همان پوشه بالا می‌آید.

```bash
cd web
npm install
node node_modules/vite/bin/vite.js build   # خروجی در ../docs
```

همه‌چیز در مرورگر اجرا می‌شود: جدول‌های رمز داخل باندل است و هیچ درخواست شبکه‌ای برای فایل شما نمی‌رود.

**تست پاریتی (پایتون در برابر جاوااسکریپت):**

```bash
node web/test/verify.mjs <پوشه حاوی .npvt>
python verify.py           <پوشه حاوی .npvt>
# هر دو باید برای هر فایل هش SHA-256 یکسان بدهند
```

وضعیت فعلی: **۱۴ از ۱۴ فایل نمونه، خروجی بایت‌به‌بایت یکسان.**

## فرمت `.npvt`

```
NPVT1\n<base64>,<base64>,<base64>
```

هر توکنِ base64 یک بلاک است:

| بخش | طول | توضیح |
|---|---|---|
| counter/nonce | ۱۶ بایت | مقدار اولیهٔ شمارندهٔ CTR (big-endian) |
| ciphertext | باقی‌مانده | با XOR کردن کی‌استریمِ خروجیِ جدول‌های white-box باز می‌شود |

هستهٔ رمز یک تبدیل ۱۶ بایتی با جدول‌های `tyBoxes`، `mbl`، `xorTable` و `tboxesLast` است. پیاده‌سازی از سورس Go پروژهٔ [Pantegnos](https://github.com/FrontierTM/Pantegnos) (MIT) استخراج و به پایتون و جاوااسکریپت پورت شده است.

**نتیجه روی نمونه‌ها:** ۱۴ از ۱۵ فایل (همهٔ `.npvt`) باز شدند — کانفیگ‌های V2Ray (VMess/VLESS + TLS/WS) روی سرورهای Cloudflare و اروپایی، به‌همراه `lockConfig` کانفیگ‌ساز.

## فرمت `.npv` (NPVS نسخهٔ ۵) — پشتیبانی نمی‌شود

ساختار این فایل‌ها استخراج شده ولی محتوای آن با کلید متفاوتی رمزنگاری می‌شود و ابزار عمومی برای نسخهٔ ۵ پیدا نشد (Pantegnos فقط نسخهٔ ۱ را می‌شناسد):

```
offset 0     : "NPVS" | u8 ver=5 | u32BE hdrLen=477 | header(477 بایت، رمزنگاری‌شده)
offset 486   : 12 بایت nonce
offset 498   : u32BE bodyLen=20532
offset 502   : body  -> "NPF\x01" | 32 بایت digest | u16BE تعداد رکورد=325
               سپس 324 رکوردِ [u16BE type=1..324][u32BE len][داده]
               و یک رکورد [type=0xFFFF][len=4884][payload اصلی]
offset 21034 : 64 بایت امضا
```

نیازمند RE نسخهٔ جدید NPV Tunnel (با JADX) است.

## ساختار مخزن

```
decrypt_npvt.py      ابزار خط فرمان پایتون
npv_tables.json      جدول‌های white-box (مشترک بین پایتون و وب)
verify.py            تست پاریتی پایتون
web/                 سورس اپ React (Vite + Tailwind v4)
web/test/verify.mjs  تست پاریتی جاوااسکریپت
docs/                خروجی build — همان GitHub Pages
```
